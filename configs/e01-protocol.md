# E01 protocol freeze — records baseline

**Protocol:** `e01-records-v1`

**Claim tier:** development signal

**Condition:** canonical representation with explicit primitive operations

**Owner:** Research B / Pyrrha

**Execution:** Eido, WSL-first
**Independent review:** Vesper

## Question

Can the pinned small local model emit the exact result of a bounded structured-record
transformation when the canonical records and primitive operations are supplied?
This is a baseline for the later representation-and-reusable-skills study. It is
not a test of hidden-program discovery: the operation representation is part of
the candidate-visible condition.

## Frozen task package

- 32 deterministic episodes generated by `scripts/e01_records.py`.
- Development split: requested seeds `1000–1007` (8 episodes).
- Held-out final split: requested seeds `2000–2019` and `2021–2024` (24 episodes; `2020` is excluded because the generator's deterministic nonempty retry collides with requested seed `2019`).
- Five records per episode; the generator records any effective seed caused by
  its deterministic nonempty-task retry.
- Candidate input is the R03 candidate payload: canonical records, explicit
  primitive operations, query, and declared budget. It excludes answer,
  scorer-side latent program, generator seed, split, and provenance fields.
- The candidate manifest and independent reference answers are separate files.
  The execution plan freezes their byte hashes before model invocation.

## Model and decoding

The model identity is read from the merged R02 readiness record, not restated as a
new artifact choice: `Qwen/Qwen2.5-1.5B`, revision
`8faed761d45a263340a0528343f099c05c9a4323`, `bfloat16`, with the recorded
artifact hashes. No training, tuning, prompt search, ablation, or external
service is allowed.

The model receives one deterministic prompt per episode and must emit exactly one
JSON array of result records with no surrounding prose. Decoding is greedy:
`do_sample=false`, `temperature=0`, `top_p=1`, `max_new_tokens=256`, one attempt,
no retries. Invalid JSON, a non-array, a missing output, or an exact mismatch is
incorrect and receives an explicit error class.

## Scoring and evidence

`e01-records-scorer-v1` parses predictions independently from the generator and
compares canonical JSON values against the frozen reference-answer file. It
reports development and final aggregates, per-episode error classes, scorer and
manifest hashes, model/artifact identity, wall time, peak VRAM/RAM, failures, and
limitations. Raw predictions and full reference answers remain in run storage,
not Git; the committed report contains aggregates and reviewable provenance only.

The final split is not inspected for tuning. This run has no learned library,
compound-operation discovery, retry, or second condition. Therefore its only
claim is a bounded development signal for this explicitly supplied structured
representation. It cannot establish broad reasoning, transfer, or practical
assistant capability.

## Stop conditions

Stop and preserve the run if the pinned artifacts, episode/reference hashes,
scorer revision, resource capture, or candidate boundary do not match the plan;
if the model cannot load; if an episode times out or produces malformed output;
or if any authorization field does not name the exact run. Do not silently rerun
or alter the protocol after seeing final outputs.
